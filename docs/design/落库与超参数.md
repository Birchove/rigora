## 1. 落库内容

与当前 SQL schema / `ResearchSession` payload 对齐。权威业务状态是 `research_sessions.payload` 整包；下列分表服务锁、恢复、文件、事件和审计。

### 项目与研究状态

| 内容 | 落点 |
|---|---|
| Project | `projects`（含 `version`、当前 `session_id`、`is_demo`） |
| ResearchSession | `research_sessions.payload` JSON：idea、review、plan 候选、check history/round、current task、main result、validation queue/result、plan revision、writing guidance |
| SessionPhase | `research_sessions.phase` 列（与 payload 同步） |
| 封存的旧 cycle | 同一 `project_id` 下多行 `research_sessions` |

### 运行与审计

| 内容 | 落点 |
|---|---|
| Session Events | `session_events`（递增 `sequence`，供 SSE 重放） |
| Outbox | `outbox_events` |
| Agent Runs | `agent_runs`（lease / cancel / `input_snapshot`） |
| **每次 Agent Run 的 Config Snapshot** | `agent_runs.config_snapshot`（由 `hyperparameters.run_config_snapshot()` 写入） |
| Agent Outputs | `agent_outputs`（`prompt_version` + 结构化产出） |
| Processed Commands | `processed_commands` |
| Conversation Turns | `conversation_turns` |

### 研究资产

| 内容 | 落点 |
|---|---|
| 上传文件 | 磁盘 `data/uploads/{project_id}/{document_id}/source.bin`；元数据在 `documents` |
| Parsed Markdown / Chunks | `document_chunks`；parse 尝试在 `document_parse_jobs` |
| Literature Records | `literature_records` |
| Project Literature | `project_literature`（`selected` / `query_id`） |
| Retrieval diagnostics | 写入 session / agent 产出中的 `RetrievalDiagnostics`，不另建表 |
| Validation type 目录 | `validation_types` |
| Journal 导出缓存 | `research_exports`（权威 journal 仍从 session + literature + events 现算） |

不落库：API key、system prompt、模型 CoT、原始 provider payload、完整未筛选文件字节、`ProjectView` / `allowed_commands`、SSE 心跳、未提交的前端 draft。

## 2. 超参数

**唯一调试入口：** `src/research_mentor/hyperparameters.py`  
改该文件即改变进程默认值（未设置对应 `RESEARCH_MENTOR_*` 环境变量时）。每次 Agent run 会把当时的快照写入 `agent_runs.config_snapshot`，避免事后改文件改写历史判定。

| 参数 | 当前值 |
|---|---:|
| Scoring rule version | `v1.1` |
| Key Insight Pass Score | `6.0` |
| Check 最大循环次数 | `5` |
| Check 五维权重 | `0.20 / 0.25 / 0.20 / 0.20 / 0.15` |
| research_fit 下界 | `3.5` |
| novelty 下界 | `3.0` |
| research_value 下界 | `3.0` |
| testability_feasibility 下界 | `3.0` |
| evidence_support 下界 | `2.5` |
| low / mid / high 候选数 | `1 / 2 / 3` |
| RAG Relevance Threshold | `0.3` |
| Working Retrieval TopK | `10` |
| Retrieval Candidate Limit | `200` |
| Document Chunk Size | `4000 chars` |
| Chunk Overlap | `200 chars` |
| Working Context Budget | `12000 chars` |
| Compact Summary Max Size | `2000 chars` |
| Model Request Timeout | `30s` |
| Run Timeout | `120s` |
| Run Retry Limit | `3` |
| Schema Repair Retry | `2` |
| Run Lease / Renewal | `30s / 10s` |

Check 通过条件：`final_score >= 6.0` **且** 五维均不低于上表下界。Agent 仍只输出原始分数，不下否决；Harness 按 `hyperparameters.py` 计算。

`RAG Threshold / TopK / Chunk / Context Budget` 可通过 Eval 调整；`Pass Score / 维度下界 / Check 权重 / 最大循环次数 / 候选数` 属于产品规则，修改后应同步提高 `SCORING_RULE_VERSION` 并更新 Eval。
